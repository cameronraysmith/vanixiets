## Why

The skills library must install three ways from one tree: the fleet's hermetic Nix build with apm in it (R1), apm users of this repository as a marketplace (R2), and Claude Code or the Claude desktop app adding `cameronraysmith/vanixiets` (R3). Today each group carries a hand-kept root `plugin.json`, versions sit in four places, the apm marketplace file is regenerated by hand, R3 has no file on `main`, and apm 0.38 broke the build (the ninth apm-caused break). Experiments on 2026-11-23 showed the root `plugin.json` is dead weight under apm 0.38, that one `apm pack` run plus one jq filter yields both marketplace files, and that Claude installs all 18 skill groups from the existing `.apm/skills` directories.

## What Changes

**apm 0.38 adaptation (stage 1)**
- From: llm-agents at apm 0.36.0; mattpocock/skills as a whole-repository dependency; `apm-marketplace-validate` counting `.claude/rules` for instructions groups.
- To: llm-agents at apm 0.38.0; mattpocock's 25 plugin skills listed explicitly so it deploys flat; instructions groups recognised by the fragments apm stages.
- Reason: 0.38 deploys a plugin-manifest dependency whole (`tdd` vanished) and stopped writing `.claude/rules`.
- Impact: non-breaking; all 177 composed skill directories byte-identical to `main`'s on aarch64-darwin and x86_64-linux.

**Compose regulators (stage 2)**
- From: the build checks 177 skill names and 26 hand-picked paths; `$out` carries a random installation id; nothing compares mattpocock's list with upstream.
- To: the build compares every first-party skill with its source byte for byte, every remote skill with a committed content hash, and the two trees with each other; mattpocock's list must equal its upstream plugin manifest; `--no-frozen` is explicit; the installation id is removed.
- Impact: a skill-tree change from an apm bump fails the build instead of reaching hosts.

**Per-group files (stage 3)**
- From: `apm.yml` plus a root `plugin.json` in each of 22 groups.
- To: `apm.yml` only; the 22 `plugin.json` files are deleted.
- Impact: non-breaking for R1 and R2 (verified); Claude no longer reads a stray root version.

**Marketplace files (stage 4)**
- From: `.github/plugin/marketplace.json` in Claude's format, written by a hand-run `apm pack`; versions repeated in the root `apm.yml`; no Claude marketplace file.
- To: a generator derivation writes `.github/plugin/marketplace.json` (Copilot profile, 22 groups) and `.claude-plugin/marketplace.json` (18 skill groups, `skills: ["./.apm/skills"]`, `strict: false`, no version) from the group `apm.yml` files and the root `marketplace:` block; a check fails when the committed files differ; a second check installs every Claude plugin offline and counts its skills.
- Impact: R3 becomes available; apm users keep 22 groups.

**Consumer route and clean-up (stage 5)**
- An offline apm-consumer check for groups without remote dependencies; `just agents-marketplace-remote`, which runs the existing flake app `nix run .#apm-marketplace-validate -- --remote` after publication (a nixbot effect later); documentation for Claude users; `cameronraysmith/skills-marketplace-test` kept as the desktop fixture; the operator deletes the `claude-marketplace` prototype branch after stage 4 (operator decisions S3, which also approve publishing stage 1 with this proposal and keep a generated Copilot-format `.github/plugin/marketplace.json`).

## Capabilities

### New Capabilities
- `skill-marketplace-publication` (behavioral): what apm consumers and Claude users receive from this repository's marketplace, stated in world vocabulary.
- `skill-marketplace-publication-interface` (interface): the generated marketplace files, their generator, and the checks that keep them and the composed trees honest. Trust boundary: the checks establish what apm and Claude Code of the pinned versions do with the committed files in a build sandbox; they do not establish what the Claude desktop app, a user's own apm version, or a future Claude release does.

### Modified Capabilities
- `world-assumptions` (world): new assumptions about apm >= 0.38 and Claude's observed marketplace behaviour, each with its violation condition; A136-A140 restated for apm 0.38; designations for plugin group, marketplace, apm consumer and Claude user.
- `first-party-skill-distribution` (interface; a pre-stratification spec): the authored package no longer contains `plugin.json`, and the composed trees are compared with their sources.
- `third-party-plugin-dependency` (interface): a whole-plugin upstream is consumed through an explicit skill list that must equal its upstream plugin manifest.

## Impact

- Code: `pkgs/by-name/apm-skills-compose/{package.nix,deps.nix,skills.json}`, a new `pkgs/by-name/skills-marketplace/`, a shared group-discovery file used by the compose, the download and `modules/home/ai/skills/compose.nix`, `modules/apps/apm-{marketplace-validate,skills-install,context-compile}.sh` (identity guard), three new x86_64-linux checks under `modules/checks/`, `justfile` recipes.
- Files: 22 `modules/home/ai/plugins/*/plugin.json` deleted; `.claude-plugin/marketplace.json` added; `.github/plugin/marketplace.json` regenerated; root `apm.yml` loses `packages[].version` and `marketplace.output`.
- Docs: `modules/home/ai/plugins/README.md`, the `agent-context-vanixiets` architecture fragment, `packages/docs/.../consuming-marketplace-plugins.md`.
- Dependencies: apm and Claude Code both come from `llm-agents`; every bump re-runs the regulators.
- Not affected: home-manager delivery (the names it reads move under one key of `skills.json`), the root `apm.lock.yaml` (stays at lockfile v1).
