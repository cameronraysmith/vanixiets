Each numbered group from 1 to 6 is one pull request, merged in group order; groups 1 to 5 each end in one deploy of magnetite, D1 to D5, and group 7 holds the verification each deploy must pass before the next deploy starts.
Group 6 changes documentation only and is not deployed.
The deploy-record snippet reaches the other nine machines at their routine updates; no machine other than magnetite is deployed for this change, and none is needed for its acceptance.
Nix-managed outputs are verified by evaluating (`nix eval`), building (`nix build`) or inspecting the delivered path on the host after activation, never by reading source; each task names which.
Evidence logs go to `logs/s2-evidence/<task>-<UTC timestamp>.log`.
Every task that adds or changes a check records its evaluation cost with `NIX_SHOW_STATS=1 nix eval --option eval-cache false --raw .#.checks.x86_64-linux.<check>.drvPath` against the 0.5 GiB budget, the figure and the method together; the leading dot keeps nix from first probing `packages` and `legacyPackages` (charter v19).
Every deploy runs `logs/s2-evidence/s2-deploy.sh` (plan Task 7 Step 0), which deploys from a fresh worktree of `origin/main` only when `nixbot-logs queue` prints `Queue is empty`.
A relation within one host is a module assertion, shown able to fail by an `extendModules` override; every new check clause names its two independently defined value sources before its mutant is written.
Spec requirement names are quoted from this change's `specs/`; `DC` is `devloop-collection`, `DCI` is `devloop-collection-interface`, `FA` is `fleet-alerting`, `FAI` is `fleet-alerting-interface`, `HMC` is `host-metrics-collection`, `TSI` is `telemetry-store-interface` and `WA` is `world-assumptions`.
