# Dev-loop collection (S2) implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Copy every finished nixbot attribute and build, every gitea-mq batch event and every magnetite activation into the `devloop` database on magnetite, once each and with no free text, prove the copy complete every day with `devloop-reconcile`, install the deploy-record snippet on all ten machines, held by CI on the five x86_64-linux NixOS machine checks, and warn when more than one in ten pull-request builds of the trailing day waited over an hour to start, landed as six pull requests and five deploys of magnetite.

**Architecture:** `flake.lib.otelCollectorSchema.devloop.tables` is the one allow-list; `modules/nixos/devloop-collection.nix` renders from it the store's tables and ingest pipelines, which `greptimedb-schema` creates, the nixbot export queries and column grants, and the collector's `sqlquery`, `journald` and `file_log` receivers, whose `logs/*` pipelines reach one `otlp_http/devloop_<table>` exporter per table through a `routing/logs` connector in the ingress role.
`modules/system/deploy-record.nix` appends one JSON line per activation on every NixOS and darwin machine, held by a machine-check obligation, and `devloop-reconcile`, a daily `DynamicUser` oneshot, compares each table with its source over the previous UTC day.
The fleet evaluator gains a per-rule `database` and `language`, sending SQL rules to `/v1/sql`, and the dev-loop burn rule `PullRequestQueueWaitBurn` reads `devloop`; the gating checks `devloop-queries` (which also holds the abandonment marker against the patch's production code), R3.1 and `fleet-alert` and the on-demand container test `devloop-ingest` regulate it before deploy.

**Tech Stack:** nix flakes with flake-parts and import-tree; NixOS `services.postgresql` (PostgreSQL 16, magnetite runs 16.15) with `postgresqlTestHook`; `otelcol-contrib` 0.155.0 (`sqlquery` logs at Development, `journald` at Alpha, the file receiver named `file_log`); `greptimedb-bin` 1.2.1 with its pipeline API; `pkgs.testers.runNixOSTest` systemd-nspawn containers needing `uid-range` (magnetite); `writeShellApplication` over `psql`, `curl`, `jq` and `journalctl`; the nixbot input at `Mic92/nixbot@d020013fa` and gitea-mq at `Mic92/gitea-mq@02264515b` (`flake.lock`).

**Spec:** `openspec/changes/stand-up-devloop-collection/` — `design.md` (D1–D17), `specs/`, `tasks.md`, `brainstorm.md` (D1–D17 as accepted 2026-10-21); `logs/s2/grounding.md` (magnetite's schema, journal, store and collector as read on 2026-10-21) and `logs/s2/spike-dedup.md` (deduplication and table creation on GreptimeDB 1.2.1); the decision records under `docs/notes/development/observability/` (charter v22; ADR-004, ADR-005, ADR-009, `components/devloop-exporters.md` as amended).

## Global Constraints

- Repository: `$REPO` is the repository root (`git rev-parse --show-toplevel`), jj-colocated; never relocate `@`; commit each plan task as one change off `main@origin` per the repository's jj workflow.
- After creating or renaming any file, run `jj st --no-pager >/dev/null` before any `nix` command reads the tree, so the snapshot includes it.
- The planning pull request (this change directory and the charter v22 amendments to the decision records) lands before Task 1's pull request, after Task 1 Step 1's plan review has been decided.
- Each of Tasks 1 to 6 is one pull request, in the order of the task map; each lands through the merge queue before the next task's pull request is enqueued.
- Before every commit run `nix fmt` and keep its log; a commit whose tree fails `nix fmt -- --fail-on-change` is not pushed.
- Evidence: long or output-heavy commands are captured as `<command> 2>&1 | tee logs/s2-evidence/<task>-<slug>-$(date -u +%Y%m%dT%H%M%SZ).log`, with any filter after the `tee`; `logs/` is git-ignored.
- Nix-managed outputs are verified by `nix eval`, `nix build`, or inspecting the delivered path after activation, never by reading source; each step says which.
- Evaluation cost: every new or changed check records `NIX_SHOW_STATS=1 NIX_SHOW_STATS_PATH=/tmp/<check>-stats.json nix eval --option eval-cache false --raw .#.checks.x86_64-linux.<check>.drvPath` and the stats file's `.gc.totalBytes` and `.cpuTime` against a budget of 0.5 GiB (536870912 B), the figure and this method recorded together; the leading dot keeps nix from first probing `packages.x86_64-linux` and `legacyPackages.x86_64-linux`, which adds about 114 MB that is not the check's (charter v19).
- Every check clause relates two independently defined values, and each step that adds a clause names them before its mutant is written; a property of one module's own settings, or a relation within one host, is an assertion in that module or host, shown able to fail by an `extendModules` override of the host's configuration, never a check clause (S1 review F5; S3 review F3, F6).
- Every runtime clause, and every `devloop-reconcile` clause, has a negative control shown to fail: the `devloop-ingest` case named for it, or a forced failure on magnetite.
- Every case touching ingest in `devloop-ingest` starts the store, the schema job and the collector together and asserts each exporter's `otelcol_exporter_send_failed_log_records` is zero after its first send (S1 retrospective §6).
- import-tree loads every `.nix` file under `modules/`, so each `.nix` file there is a flake-parts module; non-module inputs (SQL, Python, slog fixtures, JSON) use other extensions.
- Pins: `greptimedb-bin` 1.2.1; `otelcol-contrib` 0.155.0; PostgreSQL `pkgs."postgresql_${flake.lib.devloopCollection.postgresqlMajor}"` (`"16"`; magnetite runs 16.15), the major version `flake.modules.nixos.devloop-collection` asserts of magnetite's `services.postgresql.package`; the `nixbot` input at `d020013fa0db4ec40ddd0593b9bfce65fedbff64`, whose migrations `0001` to `0037` equal those magnetite has applied (design Context); the `gitea-mq` input at `02264515bfce00e24361ae6a250906bc7531f64c`; vendor source is read at those revisions before depending on a behaviour, and cited `owner/repo@rev:path:line`.
- Store: HTTP at `http://127.0.0.1:4000`; SQL as `POST /v1/sql?db=<database>` with form field `sql`; pipelines as `POST /v1/pipelines/<name>?db=<database>` with `-F file=@<yaml>`; accounts `admin` (`rw`, the schema job only), `collector` (`wo`, the exporters), `regulator` (`ro`: `greptimedb-envelope`, `fleet-alert`, `devloop-reconcile`); every identifier in rendered SQL is double-quoted, because `status` is a reserved word in GreptimeDB's parser (`logs/s2/spike-dedup.md` DDL).

  - `ci_build`: `build_id` int64, `created_at` timestamp, `started_at` timestamp, `finished_at` timestamp, `eval_duration_ms` int64, `status` string, `pr_number` int64, `branch` string; key `build_id`; time index `finished_at`.
  - `batch_event`: `batch` int64, `msg` string, `build` int64, `sha` string, `failed_check` string, `members` int64, `landed` int64, `ejected` int64, `builds` int64, `flaky` boolean, `ts` timestamp; key `batch`, `msg`; time index `ts`.
  - `deploy_record`: `host` string, `closure` string, `previous_closure` string, `ts` timestamp; key `host`; time index `ts`.
  - Every column but the time index is nullable; the time index is `TIMESTAMP(6) NOT NULL`; tables are `ENGINE=mito WITH ('append_mode' = 'false', 'sst_format' = 'flat')` with no `ttl`, inheriting `devloop`'s 365 days, so `services.greptimedb.tableTtls` stays empty.
- nixbot queries (design D6): datasource `host=/run/postgresql dbname=nixbot user=opentelemetry-collector sslmode=disable`; `collection_interval: 60s`; `tracking_column: finished_at`; `tracking_start_value: "1970-01-01T00:00:00.000000Z"`; `body_column: body` over `'' AS body`; every value `coalesce(<expr>::text, '')`, every timestamp `to_char(<col> AT TIME ZONE 'UTC', 'YYYY-MM-DD"T"HH24:MI:SS.US"Z"')`; predicate `<finished_at> >= least($1::timestamptz, now() - interval '5 minutes')`, `ORDER BY <finished_at>`, `LIMIT 10000`; `abandoned` is `(a.status = 'ignored_failure' AND a.error IS NOT DISTINCT FROM '<abandonMarker>')::text`, never a pattern match; no `error` column is ever selected.
- Abandonment marker: `not finished when the required attributes had settled`, the Python string literal of `modules/nixos/nixbot-abandon-optional-attributes.patch:146`, `:379`, `:451`.
- Column grants (design D10): `opentelemetry-collector` on `builds (id, project_id, commit_sha, branch, pr_number, status, created_at, started_at, finished_at, eval_duration_ms)`, `build_attributes (build_id, attr, system, status, cached, error, drv_path, outputs, started_at, finished_at, eval_wall_ms, eval_alloc_bytes)`, `projects (id, owner, name)`; `devloop-reconcile` on `builds (id, branch, finished_at)`, `build_attributes (build_id, attr, finished_at)`; no index, view, function or trigger is created in nixbot's database.
- gitea-mq: `journald/gitea-mq` with `units: [gitea-mq.service]`, `grep: 'msg="batch (formed|built|landed|bisecting|done)"'`, `start_at: beginning`, `storage: file_storage`, `journalctl_path` a wrapper running `journalctl --boot=all "$@"` (systemd 261 limits `--follow` to the current boot); `key_value_parser` from `body.MESSAGE`; keep-list `batch`, `msg`, `build`, `sha`, `failed_check`, `members`, `landed`, `ejected`, `builds`, `flaky`; body removed; `ts` is the journal's `__REALTIME_TIMESTAMP`.
- Deploy record: `/var/log/deploy-record.jsonl`, mode `0644`, one line `{"host":"<networking.hostName>","closure":"<$systemConfig>","previous_closure":"<readlink -f /run/current-system>","ts":"<date -u +%Y-%m-%dT%H:%M:%SZ>"}`, `previous_closure` omitted when `/run/current-system` does not exist; NixOS `system.activationScripts.deploy-record` without `supportsDryActivation`; darwin `system.activationScripts.postActivation`.
- Collector components: receivers `sqlquery/ci_attribute`, `sqlquery/ci_build`, `journald/gitea-mq`, `file_log/deploy-record`; processors `resource/devloop-<table>` setting `vanixiets.database = devloop`, `vanixiets.table = <table>` and `host.name`; source pipelines `logs/devloop-<table>` (receiver → `memory_limiter`, `resource/devloop-<table>` → `forward`); ingress `routing/logs` (one route per table on both attributes), `logs/ingress` (`forward` → `memory_limiter` → `routing/logs`), `logs/devloop-<table>-out` (`routing/logs` → `resource/strip-database`, deleting `vanixiets.database` and `vanixiets.table` → `otlp_http/devloop_<table>`); each `otlp_http/devloop_<table>` posts to `http://127.0.0.1:4000/v1/otlp` with `x-greptime-db-name: devloop`, `x-greptime-log-table-name: <table>`, `x-greptime-pipeline-name: devloop_<table>`, `x-greptime-hints: auto_create_table=false`, `basicauth/store`, infinite retry and a `file_storage` queue; no `logs/*` pipeline takes the `otlp` receiver.
- Queues (bytes sizer, one `file_storage` directory): `fleet` 400 MiB, `agent` 48 MiB, `devloop` 4 MiB, `devloop_ci_attribute` 32 MiB, `devloop_ci_build`, `devloop_batch_event` and `devloop_deploy_record` 4 MiB each; total 496 MiB, below 512 MiB.
- Units on magnetite: `devloop-pg-grants.service` (oneshot as `postgres`, `RemainAfterExit`, `after` `postgresql.service`, `postgresql-setup.service` and `nixbot.service`, `wantedBy` `multi-user.target`, no `partOf`, once per boot, and at an activation only when the unit changes, waits up to 300 s for its columns and grants; a grant a later nixbot migration removes is detected by the collector's query errors and reconcile C1/C2, not repaired); `devloop-reconcile.service` (oneshot, `DynamicUser`, `SupplementaryGroups = [ "systemd-journal" ]`, `LoadCredential = [ "regulator-password:<greptimedb-users regulator-password path>" ]`, `MemoryMax = "128M"`, `TimeoutStartSec = "10min"`, `after` `postgresql.service`, `greptimedb.service`, `greptimedb-schema.service`, `devloop-pg-grants.service`, no `wants`); `devloop-reconcile.timer` (`OnCalendar = "*-*-* 02:15:00 UTC"`, `Persistent = true`).
- OOM order on magnetite: nixbot evaluator 900 > store 500 > collector 300 > alert evaluator 0; `devloop-reconcile` sets no `OOMScoreAdjust` (S2 review F7).
- `regulator-password` holders on magnetite: `devloop-reconcile`, `fleet-alert`, `greptimedb-envelope`; notified units gain `devloop-pg-grants` with its unit in Task 3 and `devloop-reconcile` with its unit in Task 4.
- Burn rule `PullRequestQueueWaitBurn`: `database = "devloop"`, `language = "sql"`, `for = "1h"`, severity `warning`, no presence selector, `expr` exactly `SELECT CAST(sum(CASE WHEN c.started_at > c.created_at + INTERVAL '1 hour' THEN 1 ELSE 0 END) AS DOUBLE) / count(*) AS value FROM ci_build c JOIN (SELECT build_id, min(finished_at) AS first_finished FROM ci_build GROUP BY build_id) f ON c.build_id = f.build_id AND c.finished_at = f.first_finished WHERE c.pr_number IS NOT NULL AND c.started_at IS NOT NULL AND c.finished_at >= now() - INTERVAL '24 hours' HAVING count(*) >= 10 AND sum(CASE WHEN c.started_at > c.created_at + INTERVAL '1 hour' THEN 1 ELSE 0 END) * 10 > count(*)`, counting each build's first attempt only, the row with the smallest `finished_at` for its `build_id` (plan review F1); every other rule `database = "fleet"`, `language = "promql"`.
