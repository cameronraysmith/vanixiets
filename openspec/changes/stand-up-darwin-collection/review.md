## Report

### F1: the vocabulary block would drop main's rows

`verify.md` §8a.3 holds the `comm` output.
The 14 rows besides `collected host` are the browser-relay and dashboard rows main gained after #3733.
S4 met the same shape at its archive and retook the affected block from main with its rows re-added.

### F2 and F3: the deltas describe a darwin floor and clauses the code does not have

6.6a changed the floor per platform and added `fleetKeptBelowFloor`, and 5.3a moved C5 to physical footprint; the deltas took the second change and not the first.
The `otel-collector-darwin` scenarios were written before the check and name clauses for the limiters and the routing that were not built.
Both would sync into main as written, so each needs either the clause or the reworded text before 9.6.

### F4: memory evidence is resident where the requirement asks for footprint

5.3a's decision kept C5's limits on one `top` reading and 105 passing runs, which tasks.md 6.1 records as the operator's.
The scenario still states the earlier order, and 8.6's figures are resident sizes that C5 no longer bounds.
8.1's sampler records footprint every 60 s, so its window can supply the 24 h maximum and, if stibnite sleeps in it, the post-sleep one.

### F18: process memory is stored per process, not per executable

The darwin `otelcol-process` renders the same `groupbyattrs/compact` and `metrics_transform/process` stages as the NixOS agent (`modules/lib/otel-collector-darwin.nix:272-288`), and `aggregate_labels` groups only points whose attributes and nanosecond timestamp are equal, which separately stamped processes never are (`logs/cam88-evidence/diagnosis.md`).
On stibnite a summed name would store one point a minute; `plugin-container` stores 3.07, `python3.14` 2.21 and `otelcol-contrib` 1.99, and `zen`, a single process, matches `ps` to within a few MiB.
The darwin floor and keep-list of 6.6a were chosen from stored name counts, so the bound they give, at most 17 names an hour, holds for the behaviour as deployed; what is false is the meaning of a stored value and of the memory alerts' attribution.
This report's earlier placeholder for F18 said the sum happened only for points sharing a millisecond; that claim is withdrawn here.
