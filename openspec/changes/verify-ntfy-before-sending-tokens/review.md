## Report

### F1: caddy's admin endpoint reads the key for any local account

The design treats the admin endpoint as a read-only evidence source (D8 step 1, from the plan review's F14), and A81's evidence lists the key's owner and mode.
caddy's admin API configures the running process, which runs as the key's owner, so the effective reader set is every account and service on cinnabar, among them the services caddy itself proxies.
The stored key in caddy's storage was reachable the same way since 2026-01-27, so this is not new exposure on cinnabar; what is new is that the change's records now state a boundary that excludes it.
A unix socket with mode `0600` keeps `caddy reload` working for the unit and removes every other account, which the follow-up can show with the same `GET` as `nobody` failing.

### F2: one key, every name, a public repository

O11 decided that a reinstall must not mint a root nobody trusts, and accepted the key in the repository for that.
The records state the cost as "a certificate every `ntfy.zt` client trusts".
The root, however, is a general CA on stibnite and blackphos, installed for every purpose, and in their nix CA bundle, and it is a user CA on the operator's phone.
A future loss of the one age key, or of cinnabar's age key, therefore exposes every HTTPS name those devices use, for as long as the root is trusted, and the ciphertext stays in the public history after any rotation of recipients.
A name constraint can only come with a new root, so the fix belongs to a rotation; the records can state the scope now.

### F9: the scan's reach

The scan's clauses are sound for what they judge, and its seven mutants each fail their clause.
The gap is at the one remaining client's input: `"$@"` lets a caller pass any curl option, and curl takes the last `--cacert` and honours `-k` wherever it appears.
Extending clause A to `ntfy-send` command lines keeps the declared-client model and costs one pattern and one mutant.

### Design adherence

The code on `origin/main` matches D1 to D6 and D10 to D13 as written: `ntfy-send` exports `NTFY_CACERT` and the store curl on every platform and fails before curl without it (`ntfy-send.sh:38`, `package.nix:34-37`); the hooks post through it and `gate-dangerous-commands` holds it; the TLS test, the token test, the scan with its lists and mutants, `flake.lib.caddyRootCheck` with its legs, the weekly unit and timer, `caddy-local-root` with its two clauses, the generator with its failing script, the VM test, the removal of CR and `zt-services-trust`'s switch to RV are each where the layout puts them.
D10's `neededFor = "services"` is not written in `caddy-root-ca.nix`, and clan's default supplies it [INFERENCE: from the deployed path under `/run/secrets`, which is the services phase's].
D7's rotation and D8's order are documentation and sequence; D7's step 3 claim is F7 (b), and D8's deviations are F11.
No code smell rises to a finding; the comments added are rationale or option documentation.

### The four questions

Critical oversights: none that falsifies a deployed guarantee; F1 and F2 are the boundary statements that are wrong.
Significant architecture improvements: a root-only admin socket on cinnabar (F1) and a name-constrained root at the first rotation (F2).
Checks that cannot fail or restate their line: `configured root` partly restates the options that render the block, as the plan review's F8 accepted, and `pkiDropped` shows it can fail; clause B accepts `--cacert` anywhere in the client file, which the token test's exact argument lists back; properties nothing covers are the rotation (F8), the caller's arguments (F9) and the expiry notice's delivery (F12).
Mechanisms costing more than they protect: none; the scan and legs cost 151,979,344 B at `bbbc8da89`, under a third of the budget.
