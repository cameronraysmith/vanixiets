# Comment cleanup

## Scope

This skill is the operational enforcement arm of the code-comments policy defined in `preferences-style-and-conventions` §"Code comments"; it does not restate that policy but drives it over real trees.
It is a workflow sibling to `preferences-git-history-cleanup`, and like it, a comment-only cleanup is a legitimate standalone change.

## The tool: uncomment

The workflow is built on this repository's `uncomment-bin` package (`pkgs/by-name/uncomment-bin`), a tree-sitter comment remover whose bare invocation is allow-by-default, not deny-by-default: it preserves TODO, FIXME, HACK, XXX, NOSONAR, the `~keep` marker, doc comments, and linting directives (eslint-disable, clippy::, noqa, and similar) unless told otherwise, and removes everything else.
`--remove-todo`, `--remove-fixme`, and `--remove-doc` opt back into removing those specific preserved categories one at a time, and `--no-default-ignores` drops every built-in preservation rule at once, which is the only invocation that behaves deny-by-default.
It offers `--dry-run` and `--dry-run --diff` (no writes), `--check` (a dry run that prints each removable comment as `path:line:col: text` and exits 1 if any would be removed), a `scan` subcommand that reports every comment with its verdict and preservation reason without writing anything, a `~keep` always-preserve escape hatch, path exclusion via `--exclude <GLOB>` or the `exclude` config key, and case-insensitive substring `preserve_patterns` in a `.uncomment.toml` (global merges into per-language).
A `~keep` on any line of a contiguous run of line comments keeps the whole run (scan reports the neighbours as `extended_by_neighbour_marker`), so one marker can shield prose you meant to cut.
Unknown config keys are a load error that aborts the run, and the legacy `.uncommentrc.toml` name is still read but prints a deprecation warning.
Its "warning: removed N potentially important comment(s)" message is not a dependable signal: a small `--no-default-ignores` run that strips SPDX and `noqa` lines prints no warning at all, while a large, heterogeneous tree can trigger it under plain default flags (verified against this repository), so its absence is not evidence the diff needs no review.
The behavior this section and the rest of this skill describe was established against `uncomment-bin` 3.10.2.

## Why uncomment is never run unattended

uncomment cannot be a repo-wide mutation engine; linting and formatter directives (`fmt: off`/`fmt: on`, `prettier-ignore`, `eslint-disable`, `noqa`, `type: ignore`, `shellcheck disable`, and the rest of that family) are preserved by default anywhere in a file — confirmed by placing one past line 10 — not only near the top.
SPDX/license/copyright word forms (`SPDX-License-Identifier`, `Copyright`, `License`, `@license`, `@copyright`) are preserved by default anywhere in a file, but code-generation "DO NOT EDIT"/"DO NOT MODIFY"/"Code generated"/"Generated by" markers are protected only within the first 10 lines, confirmed by moving an identical marker from line 10 to line 11 and watching it start getting removed, so those markers are unprotected outside that header window.
It misses `# SAFETY:`, `# -*- coding: utf-8 -*-`, `WORKAROUND`, and bare `(c)` notices by default — no built-in pattern recognizes them — and it intrinsically deletes hand-written "why" prose that carries none of its recognized keywords, which is the exact rationale category the policy protects and the real reason a human-plus-agent classification gate stays between census and apply.
Its language list is not an allowlist (shell, yaml, python, javascript, and rust were all processed in the same run during verification), and while it respects `.gitignore` by default, a committed-but-generated or vendored tree that is not gitignored is walked and modified like any other source unless it is excluded with `--exclude` or the `exclude` config key.

## The workflow

Operate on one subdirectory tree at a time rather than the whole repository, e.g. `uncomment modules/apps --dry-run --diff`.

### 1. Census

If the target tree has no `.uncomment.toml` and touches languages the hardened `uncomment.toml` template doesn't cover, run `uncomment init --comprehensive` first to generate a project-scoped baseline, then layer the template's residual-gap patterns (`SAFETY:`, the coding declaration) on top.
Take a complete candidate-removal inventory without touching files.
`uncomment scan` is the census primitive: `--only removable` limits the report to what a real run would strip, `--group-identical` collapses repeated comments into one record with a site list so a large tree stays decidable, and every record carries a stable id that `uncomment keep --from <report>` can later turn into `~keep` markers.
The "important" warning is not a reliable census seed either way, so treat every removable record as a classification candidate regardless of whether a warning showed up.
On a large subtree, add `-j 0` to auto-detect the thread count instead of the default single-threaded scan.

```bash
uncomment scan modules/apps --only removable --group-identical --format text -j 0
uncomment modules/apps --dry-run --diff -j 0
```

### 2. Classify

Fan out the candidate removals across parallel agents, sorting each into `mandatory-keep`, `essential-keep`, or `slop-cut`, seeded by the `preferences-style-and-conventions` §"Code comments" load-bearing carve-out list.
When a recurring pattern needs to be spared for this run without editing the shared config, re-run census with `-i "<pattern>"` to confirm the narrower diff before committing to that classification.
When a comment must survive permanently rather than for one run, write the decision back with `uncomment keep --id <id>` (or `--from` a filtered scan report) instead of hand-editing `~keep` markers, and remember that `~keep` extends over the whole contiguous comment run.
Adversarially verify every proposed cut before applying, treating a wrong deletion of a rationale comment as high-severity.

### 3. Apply

Delete only confirmed slop, in place; essential and mandatory comments never move, so there is no lossy strip-then-restore round trip.
Run the real removal with `-q/--quiet` once the diff has already been reviewed in census, since apply no longer needs the per-file output or inline diff that step produced.
Afterwards, `uncomment <tree> --check` exits 0 only when nothing removable remains, which confirms every surviving comment is either built-in-protected, pattern-protected, or `~keep`-marked.

### 4. Commit

Group the applied cuts by subsystem into a small number of atomic commits; never commit one comment per commit.

## Safety gates

Exclude vendored, generated, and upstream-mirrored trees that are not already gitignored, with `--exclude <GLOB>` per run or the `exclude` config key, since uncomment's language list is not an allowlist.
Watch for cross-branch file collisions with any active VCS chains, and keep dry-run-first discipline before every apply.
A hardened starting config ships beside this skill at `uncomment.toml`.
3.10.2 already preserves formatter and linting pragmas, XXX, `tflint-ignore`, and license/copyright word forms by default anywhere in a file, and preserves "DO NOT EDIT"/"Generated by" markers by default within the first 10 lines, so the config only needs to close what's still missing at any position: `SAFETY:`, the `-*- coding: -*-` declaration, `WORKAROUND`, bare copyright symbols, generated markers outside the header window or without the recognized phrasing, bare `rustfmt`, and managed-block sentinels.
Copy it to the target repository root as `.uncomment.toml` and treat it as a targeted-assist config for a specific run, not a standing repo-wide policy; a pre-existing `.uncommentrc.toml` there still loads but should be renamed, and any key 3.10.2 does not recognize will abort the run.
