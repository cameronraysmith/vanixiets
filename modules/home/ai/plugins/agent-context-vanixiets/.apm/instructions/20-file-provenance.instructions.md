## Generated agent context files

The repository-root `AGENTS.md` and `CLAUDE.md`, along with `GEMINI.md`, `SOUL.md`, and `CRUSH.md` if they appear, are generated artifacts.
The committed `.gitignore` covers all five through unanchored rules naming the family of agent context filenames, so none of them ever enters git history from this checkout.
See "Agent context composition" in this package for the generation mechanism: devshell entry regenerates `AGENTS.md` and `CLAUDE.md` whenever they are missing or their inputs changed, and `just agents-context` forces it; treat any of these files you find on disk as a build output, never as something to hand-edit or commit.

## Machine-local directories that are not actually ignored

Neither `.claude/` nor `.factory/` (droid's equivalent) is present in a fresh checkout of this repository, and neither is covered by any rule in the committed `.gitignore`.
`.git/info/exclude` is also empty in this checkout, so nothing — not `.claude/settings.local.json`, not any other per-checkout file — is currently excluded through it either.
If either directory is created and gains content that should stay machine-local, add an ignore rule at that point rather than assuming one already exists.

## Deliberately tracked exceptions

`openspec/changes/archive/` is tracked despite `archive/` being a common ignore pattern elsewhere in the tree; the root `.gitignore` anchors its `/archive/` rule to the repository root specifically so it does not also match this path.
`terraform/.terraform/`, `terraform/.terraform.lock.hcl`, `terraform/config.tf.json`, and the deploy-key files under `terraform/` are regenerated by the terranix/terraform recipes and are git-ignored; the encrypted `tfstate` itself is safe to commit and is not excluded.
`manifests/workspace-manifest.json` and `manifests/workspace-manifest.yaml` are generated from the CUE workspace manifest, which is the source of truth, and are git-ignored.
`.agents/` holds generated state: the composition stamp `.agents/.context-inputs-sha256` and its compile key, and, only where `just agents-install` ran, a `.agents/skills/` tree materialized from `apm.yml` and `apm.lock.yaml`.
On a host where home-manager delivers skills, `.agents/skills/` should not exist, because it would shadow the user-level skills; `just agents-install` refuses there for that reason (see "Agent context composition" in this package).
